## 범위와 데이터 구분

- 주 악기: `violin` 바이올린, `cello` 첼로, `flute` 플루트, `clarinet` 표준 Bb 보엠식 클라리넷. ‘플룻’은 검색 별칭이다.
- 원자료 항목 19개(바이올린 7, 나머지 각 4), 질문 38개는 출처 문서의 통계다. 항목은 전부 미검수 메타데이터이며 실제 본문을 합성 자료로 대체했다고 주장하지 않는다.
- 모듈 계획 24개는 4악기×6슬롯의 편집 목표다. 기존 19항목과 다대다로 제안 매핑한다. 콘텐츠 완성·승인 수량이 아니다.
- 앱 후보 37개는 첨부 문서의 정확한 URL 목록이다. 초기 상태는 전부 점검 전이다. 실행·음악적 정확성·모바일·개인정보 점검은 별개다.
- 합성 데모 자료 8개·구조화 단원 16개·40분 수업안 4개를 별도 데이터로 만든다. 데모 승인은 ‘승인 절차 시연 · 교육 내용 검증 아님’이다.
- 실제 승인·공개 가능한 교재는 현재 0개다. 이전에 존재하던 PDF·SVG 파일의 존재는 배포 권리 또는 전문가 승인을 뜻하지 않는다.

P0: 책장/목록, 검색·필터·정렬, 상세·단원, 판본별 이어읽기, 북마크, 앱 후보, 교안 저장·복제·출력, 관리자 메타데이터, 검수·오류·판본 흐름, 저장 복구, 접근성 및 자동 검사.

선택 P1: 승인 근거 자료 안내, 앱별 실제 점검, 권리 확인 PDF 연결. 후속 P2: 실제 인증·서버 저장·협업·API/SSO·승인 근거 AI·동의 기반 학생 서비스. 이번 구현에서는 계정 생성, 외부 DB, 배포, commit/push, 결제, 카메라·마이크·위치, 실제 학생 정보, 분석 SDK, 외부 AI를 사용하지 않는다.

## 보존한 이전 구현의 판단

기존 저장소에는 14악기 교재 자산·631개 페이지 SVG, 38앱 레지스트리, 합성 멀티앵글/수업 미션, Worker/D1 연결 코드가 있었다. 이는 이전 구현 자산이며 이번 4악기·37후보·로컬 mock 수락 기준을 바꾸지 않는다. `docs/SOURCE_AUDIT.md`, `docs/backend.md`, `docs/webapp-bridge.md`는 당시 기록으로 보존하되 최신 권리·실행·승인 증거로 취급하지 않는다.

기존의 ‘교사 검수 전’, ‘24 목표와 19 원자료 분리’, ‘카메라/마이크·외부 AI 없음’, ‘실제 성과와 전문가 승인을 만들지 않음’ 원칙은 유지한다. 사용하지 않는 기존 컴포넌트·서버 코드는 보존하며 현재 진입점과 새 prototype 경계를 분리한다.
